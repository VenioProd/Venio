**Goal :** Clore le backlog UX validé : annulation de suppression d'issue (toast undo), flux guidé post-séance (recap → devoir → séance suivante), et reprise du dernier contexte à l'ouverture de l'espace pédagogie.

## Volet A — Dev : undo suppression d'issue

### Task A9

**Files:** Modify: `src/pages/admin/dev-workspace/index.tsx`, `DevWorkspace.css`

- [ ] Remplacer la suppression immédiate par une suppression différée :
  - `handleDeleteIssue(id)` (garder le confirm existant) : retire l'issue de `issues` localement, ferme le détail si ouvert, et enregistre `pendingDelete = { issue, timer }` où `timer = setTimeout(flushDelete, 6000)`.
  - `flushDelete()` : appelle réellement `deleteDevIssue(issue._id)` puis `loadStats(); loadOverview()`. En cas d'échec API : réinsérer l'issue dans la liste + bannière d'erreur.
  - `undoDelete()` : `clearTimeout`, réinsère l'issue dans `issues` (l'ordre exact n'a pas besoin d'être préservé : le tri/groupement la replace), vide `pendingDelete`.
  - Si une nouvelle suppression arrive alors qu'une est en attente → `flushDelete()` immédiat de la précédente d'abord.
  - Au démontage du composant (`useEffect` cleanup) : flush si en attente (utiliser une ref pour le pendingDelete afin d'éviter les closures périmées).
- [ ] Toast en bas de l'écran pendant l'attente : `Issue {identifier} supprimée — [Annuler]` (classe `.dev-undo-toast`, même zone que la bulk bar ; si la bulk bar est visible, le toast s'affiche au-dessus). Disparaît au flush ou à l'undo.
- [ ] CSS `.dev-undo-toast` : fond `#141a2a`, bordure `rgba(255,255,255,0.12)`, bouton Annuler accent `#7c5cff`.

### Task B7 : Enchaînement post-séance

```tsx
export function PostSessionFlow({ session, templates, onClose, onChanged }: {
  session: EducationSession
  templates: EducationTemplate[]   // tous kinds ; filtrer localement
  onClose: () => void
  onChanged: () => void
}) { /* ... */ }
```

Contenu — checklist de 3 étapes optionnelles, chacune avec son état « fait » (coche verte) :
  1. **Compléter le compte-rendu** : textarea pré-remplie avec `session.recap`, bouton « Enregistrer » → `updateSession(session._id, { recap })` → coche.
  2. **Créer le devoir donné** : bouton « + Créer un devoir » → rend `AssignmentForm` (de `assignment-parts.tsx`) avec `classId` de la séance et `templates` filtrés `kind === 'assignment'`. `onSaved` → coche + nom du devoir affiché.
  3. **Planifier la prochaine séance** : bouton « + Planifier » → rend `SessionForm` (de `session-parts.tsx`) avec `classId` pré-rempli et date par défaut = `session.date + 7 jours, même heure` (passer une prop optionnelle `defaultDate?: string` à `SessionForm` si le form ne permet pas déjà l'injection — vérifier sa signature réelle avant). `onSaved` → coche + date affichée.
  Footer : bouton « Terminer » (ferme). Header : titre « Séance terminée — enchaînement » + nom de la séance/classe.
- [ ] Déclenchement :
  - `SessionLiveMode.endSession()` : après le `updateSession TERMINEE` réussi, au lieu de fermer directement, afficher `PostSessionFlow` par-dessus (state local) ; sa fermeture appelle `onClose()` du live mode. Le live mode doit donc recevoir `templates` en prop (l'acheminer depuis les points d'entrée : `SessionDetailDrawer` et `session-parts.tsx` — qui reçoivent déjà ou peuvent recevoir `templates` ; vérifier le câblage réel et compléter le prop drilling depuis `index.tsx`/`ClassWorkspace.tsx` si besoin).
  - `SessionDetailDrawer` : quand le select statut passe à `TERMINEE`, afficher une mini-bannière « Lancer l'enchaînement post-séance ? [Lancer] [Ignorer] » qui ouvre la même modale.
